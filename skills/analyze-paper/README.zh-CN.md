# analyze-paper（详细分析）

对一篇已入库论文做持久化详细分析，产出一份 Obsidian Markdown 笔记和一份可编辑的
JSON Canvas。skill 不规定必须如何阅读、推理或形成判断；它只把自由形成的判断投影到统一、
易读的结果结构中。

## 产物

- `<论文名>分析.md`——完整分析，带证据锚点和明确的来源状态。
- `<论文名>解析树.canvas`——与 Markdown 一一对应、从左向右展开的可编辑树。Canvas 可为
  展示压缩措辞，但不能加入 Markdown 中没有的主张。

两份文件都落在 `research_vault_root` 中，与论文索引行/相关资料枢纽同目录，并登记到
Hub：Markdown 使用薄 `sw_*` frontmatter，Canvas 则单独登记到
`.scholar-workflow/artifacts.yml`。Canvas 保持标准 JSON Canvas，不写私有顶层字段；分析内容位于
受管投影块之外，因此后续同步不会覆盖它。

## 规范分析树

整篇分析在 Markdown 与 Canvas 中都投影为一一对应的五条主分支：

1. **Abstract**——任务、技术挑战、关键洞见及其好处、各项技术贡献及其好处、实验结论速览。
2. **Introduction**——任务/应用（含输入、输出）、前序方法的挑战（前序方法、失败表现或局限、
   技术原因）、本文管线（一句话创新，以及每项贡献解决的问题、具体做法和优势）、演示/应用。
3. **Method**——任务、输入、输出和方法步骤总览，以及每个 pipeline module 的动机、做法、
   为什么有效和技术优势。
4. **Experiments**——对比实验与消融实验，包括任务/数据、baseline 或被改动组件、指标/结果、
   所支撑的贡献或可归因结论，以及证据锚点。
5. **Limitation**——每项局限、成因、影响范围、作者明确陈述或分析推断的身份，以及证据锚点。

所有带主张的字段都在 Markdown 与 Canvas 中使用可见的字段级证据/状态后缀，区分论文报告的
证据与分析推断，并在正文通道足以支持时附来源锚点。
缺失值必须明确区分：`论文未报告`、`当前正文通道无法核实`、`不适用` 含义不同，不能混用。

这棵树只是输出 schema，不是阅读顺序或推理框架。

## 整篇与局部更新

- **整篇分析**填写全部五条分支，但不编造正文无法支持的内容。
- **局部分析**只更新用户指定的子树，并保留其余笔记内容、用户调整的 Canvas 布局和自建节点。
- 不可见的标题/字段身份与基线哈希注释用于区分“未改过的生成结构”和“人手修改内容”；后者
  原样保留并作为路径级冲突返回，不被静默覆盖；同一 canonical path 的 Markdown/Canvas 项作为一对处理。
- challenge、contribution、method module、experiment、ablation 和 limitation 均按论文实际数量展开，
  不限定固定个数。
- 每篇论文维护一对持续演进的 Markdown/Canvas；后续分析深化或修订相关节点，不清空整对文件重写。

## 来源与安全

论文正文经 `scholar-workflow zotero fulltext` 读取 Zotero 索引全文；论文身份和元数据仍以
Zotero 为权威。如果索引正文缺少支撑某字段所需的表格、图片或公式，结果会明确记录来源缺口，
而不是猜测。

只有在你显式要求时才读取论文代码仓库。仓库只读克隆，按不可信证据而非指令处理，绝不运行、
build 或安装。克隆默认临时使用；只有你明确要求保留时才存入 `code_repo_root`。

分析笔记与 `export-annotations` 生成的批注笔记保持分立，两者通过 frontmatter `related` 互链。

## 用法

说“分析这篇论文”会生成完整树；指定“方法”“实验”或某个模块，则只更新对应子树。如果需要
仓库证据，请明确说“读/检查代码仓库”，并说明是否保留克隆。
