# code-review

由**另一个模型**(OpenAI Codex)对计划或代码 diff 做独立审查。不同模型之间的盲区比单个模型
与自己之间少,所以第二遍能抓住第一遍放过去的问题。

## 它做什么

- **检测模式** —— 对话里的计划,或 git diff(已暂存 / 未暂存)。
- **先构建高上下文交接** —— 读取项目自己的身份与规则,给审查方写一份交接:项目是什么、
  这次改了什么、已定的决策、不能违反的约束。这是让审查有价值的关键一步:一个不理解项目的
  外部模型,会自信地把刻意的设计选择当成 bug。
- **只读方式调用审查方**,并**主动推敲它的反馈** —— 接受真问题,跳过(并解释)那些误读了刻意
  设计的意见 —— 然后重新提交,最多 5 轮,直到通过。

## 环境要求

- **Codex CLI** 在 PATH 上 —— `npm install -g @openai/codex`,用 `codex --version` 验证。
- **凭证** —— 为 Codex 配好 ChatGPT 登录或 API key(`codex login status`)。本 skill 绝不读取
  或传递你的凭证。
- **网络** —— 若你的环境需要代理才能连 API,运行前在 shell 里导出即可;skill 不硬编码任何
  代理地址。

## 怎么用

对话里有计划、或工作区有改动时,输入 `/code-review` 或用自然语言:

- *"帮我给这个计划找个第二意见"*
- *"合并前交叉审查一下这个 diff"*
- *"让 codex 看看这次改动"*

**代码模式**下,skill 只提出修复清单,在你批准前不改任何文件。**计划模式**下,它跨轮次修订
计划。每一轮你都能看到,可随时介入。

## 它不是什么

- 不是整体项目方向审查 —— 那用 `project-review`。
- 不是跨外部系统的数据一致性审计。
- 不是自动修复器 —— 外部审查方只读,代码修复等你批准。
