# project-review

对整个项目的只读战略快照。长时间专注工作会把注意力收窄到眼前的文件;这个 skill 退后一步,
读取项目自己的战略文档,报告「项目现在站在哪、还有什么没收尾」—— 正是工作中途最容易丢失的
全局视角。

## 它做什么

- **发现**项目的战略文档 —— 配置优先(仓库根提交的 `.project-review.md`),自动发现兜底
  (原则、目标、路线图、进度、变更史、测试覆盖)。
- **读项目自己的原则。** 若仓库根声明了审查原则(如 `AGENT.md` / `CLAUDE.md`),就按它判断。
  它不硬编码任何项目的文件名 —— 项目给什么,它就适配什么。
- **报告五个维度** —— 愿景对齐、路线进度、瓶颈与悬空、覆盖缺口、下一步 —— 缺数据的维度直接跳过。

## 怎么用

用自然语言请求项目审查,或输入 `/project-review`:

- *"给我做个项目全景"*
- *"这个项目现在什么状态?"*
- *"审视一下现在的整体进展"*

结果输出到终端。不修改任何文件,除非你明确要求保存,否则不产生文件。

## 固定文档集

想让每次运行都精确、无噪声,在仓库根提交一份 `.project-review.md`,列出你的战略文档。首次
自动发现的运行会打印一份建议配置供你复制。格式与自动发现兜底表见 `references/discovery.md`。

## 它不是什么

- 不是代码 / PR 审查 —— 需要 diff 级别的第二意见,用 `code-review`。
- 不是跨外部系统的数据一致性审计。
- 不是报告生成器 —— 它为你产出视角,不产出文档。
