# survey-topic

开放式"调研 X"请求的前门。当你说*"调研一下世界模型"*或*"帮我了解三维重建这个方向"*时,
这个 skill 先把请求的范围问清楚,再把它路由到其他 skill,自己不产持久化调研产物、不落任何文件
(唯一的例外是下面那次丢弃式的范围侦察)。

## 它做什么

一个宽泛的调研请求是欠定的:同一个主题可以是十分钟的略读,也可以是几周的深挖。这个 skill
用一段简短的 **grill**,和你**逐步商定范围**——它提议、你修正、达成一致——围绕:

- **程度** —— 你想要哪条腿的领域视野:*技术演变*视角(有哪些里程碑、技术如何演变)还是
  *重要问题*视角(什么已解决、什么还没解决、当前热点);以及你的姿态——带着假设来求证
  (精读关键几篇)还是冷启动摸地形(先铺开收集、再建树)
- **范围** —— 一个具体问题 / 一个方向 / 整个领域
- **时间窗** —— 经典奠基 / 近期进展 / 持续追踪

冷启动时往往没法盲目界定范围。这个 skill 可以先跑一次快速的**广度侦察(breadth-recon sweep)**
——广泛地读,包括非 arXiv 来源(没有论文的模型、benchmark 或项目页、实验室博客)——把领域
地形的轮廓先摸出来。这次侦察是丢弃式的:它喂给范围商定的对话,不进任何库、不落任何文件。

达成一致后,它把每一步交给拥有它的 skill:`recommend-papers`、`find-resource`、
`ingest-resource`、`build-literature-tree`、`analyze-paper`。铺地图时它会用一个手法——
**引用滚雪球**:从一篇里程碑论文出发,挖它的 introduction 和 related work 里同方向的引用,
作为搜索的种子。

## 它不做什么

- 它不产持久化调研产物、不写文件 —— 每个产物都由它委派的 skill 在各自的归属地生成;唯一
  为自己做的读取,是上面那次用来界定范围的丢弃式广度侦察。
- 它不替代 `build-literature-tree`。"画一棵树"仍直达那个 skill;本 skill 只在调研需要树时
  才路由过去,并让树跑它自己的范围界定。
- 它不是定点查找(`find-resource`)或每日 feed(`recommend-papers`)—— 那些按各自的动词
  直接触发。

## 何时触发

宽泛、开放式的开口:*"调研…"*、*"了解一下这个方向"*、*"入门这个领域"*、*"这个方向的现状
如何"*、*"帮我梳理这个领域"*。已经点明具体动作的请求会跳过本 skill,直接路由到那个动作。
