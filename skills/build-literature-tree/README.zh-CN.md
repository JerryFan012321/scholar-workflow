# build-literature-tree

围绕已有论文单元搭建清晰可读的主题知识库。**field-library-v1** 固定四个入口：

1. **01-论文列表**：完整平面列表，保留未分类、缺 PDF 和阅读未完成的论文。
2. **02-文献树**：横向时间线主干、向下主要分支、右侧局部后续；论文标题下面有简短说明。
3. **03-技术路线树**：中心向外按“研究目标 → 解决办法 → 单篇论文”展开。
4. **04-挑战洞见树**：相同外观，按“目标 → 具体问题 → 解决思路 → 单篇论文”展开。

三张图必须共存，不能互相替代。每个03/04叶端只放一篇论文，附做法说明和现有资料、分析、
论文解析树、原文入口。02标题只保留短名与年份；03/04叶端只放一句做法和紧凑导航。
详细条件、改进、限制和来源放在正文；共同阅读状态在列表说明，个别缺失在对应资料页保留，
不逐卡重复诊断。输入、验收与发布材料放在领域阅读目录之外，不混入知识内容。

安装包自带[版本化格式规范](references/field-library-format.md)、两份局部CSS样式，以及
`scripts/layout_canvas.py`确定性布局/几何检查工具。它只从标准输入读已准备好的JSON，
向标准输出生成可编辑Canvas，不读写Vault、不联网、不推断论文身份或认证科学结论。
不依赖开发仓库、原模范库、个人路径或固定论文数量。精确外观需在所选Vault启用Advanced Canvas
和附带CSS；配置步骤及原生检查要求见上述规范，不会自动覆盖其他Vault配置。

既有论文包复用原归属和路径，不为画树重复分析、复制论文或恢复用户删除的文件。
单篇论文的五分支解析树、折叠摘录、直接证据强调和图片要求继续由analyze-paper持有，不降级。

旧Mermaid概念树和`project-literature-tree`保留为明确的[兼容模式](references/legacy-concept-tree.md)；
已有单元只读清单、文献贡献/演进预览也保持独立。自动检查、安装运行、科学支持和人工评鉴分别报告。
