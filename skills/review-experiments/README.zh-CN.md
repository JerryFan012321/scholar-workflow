# review-experiments

只读整理和比较已有实验，不重跑实验、不另建看板。明确项目、Run、结果对应的
Attempt 和指标后，返回带档案链接的 Markdown 报告；选择有歧义时确认，不默认选最高分或最新结果。

回传的远端子项目结果遵守共享[项目管理契约](../../references/project-management.md)。
即便 Run 名称相同，也保留子项目身份与各自代码版本；只读分析不会接收档案、下载远端成果，
更不能把缺少回传／备份能力写成已经成功。
若原任务还要求回收实验，必须另行完成本地原始档案接收与核对；报告中写出服务器路径
不能代替 Run/Attempt。共享契约说明交接与明确实验清单的检查方法。

例如：

> 对比选定的 baseline 和 variant Run，采用各自 primary Attempt 的 accuracy
> 成果。列出全部 Attempt 历史和缺失证据，只返回 Markdown，不运行代码或改项目。

报告先说清结论，配上有依据的结果图；比较条件、配置差异与对应数值放在同一结果块，
再列执行历史及限制，不让读者跨章节寻找理解数值所需的条件。
没有可用图片或数据时明确说明，不造图、不补跑。实验与执行尝试分开，失败记录保留；
机器ID和完整哈希等核验细节不挤入正文。
单位、评测协议缺失就明确未知，不继承其他 Run 的信息；远端成果不自动下载。
不会虚构统一指标 JSON 格式，也不会把一次结果差值说成统计显著进步。

单次实验报告和多实验比较都须有能独立读懂的正文，不能只交分数表或图片集。
方法做了什么、参数的含义与作用、指标回答什么问题、图中应观察什么，遵守共享的
[充分解释规范](../../references/human-presentation.md#standalone-explanations)。
对照实验目的，明确哪些得到支持、哪些失败、哪些仍不能确定；简短总表不能让完整报告也变成提纲。
只选一次结果时不虚构 baseline 或控制实验。结构完整、证据支持和正文可读性分别判断。

多实验对比用紧凑表格记录名称、实际执行时间、目的、配置自变量和结果。
变量少时直接列值；变量多时概括关键差异，链接并核对对应执行留存的配置。
共同条件、变化项与对应结果放在同一张对比表，不拆成条件表和结果表；妨碍比较的缺失或未核实条件，
以及合成／未执行、失败或冲突状态，贴近受影响的数值标注，不只留在文末免责声明。
不能用当前工作配置或猜测补齐。

保存到项目的报告须在 VS Code 中显示图表并支持本地导航，具体见
[项目阅读器契约](../../references/vscode-project-docs.md)。其他阅读器显示成功不能代替这项验收。

详见[报告契约](../../references/experiment-review.md)。本功能自0.43.0提供；
原生阅读和人工实用性评鉴与安装分开。
