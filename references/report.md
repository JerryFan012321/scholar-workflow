# Report contract

This contract is used by [create-report](../skills/create-report/SKILL.md). A report
is a communication deliverable requested by a person or identified from the current
delivery purpose. Reports select and explain relevant materials for that purpose;
they do not replace source documents or experimental records.

## Scope and owning formats

The recognized uses include experiment-result summaries and comparisons, single
experiment or reproduction explanations, project presentations, progress updates,
technical investigations and option evaluations, handover or completion reports,
and problem investigations or retrospectives. These are open examples, not a fixed
taxonomy; one report can serve several purposes without creating several files.

Use the current task's audience, materials, medium and accepted template. Specific
chapter lists and content depth remain task-dependent; no default headings, number
of sections, word quota or image quota is imposed here. Missing source facts remain
missing; do not fill an apparent template gap by inventing facts or results.

Keep related business responsibilities explicit:

| Selected work | Owning contract |
|---|---|
| Review or compare specified Run/Attempt evidence | [review-experiments](../skills/review-experiments/SKILL.md) owns evidence selection, identities and its existing report format |
| Analyze an individual paper or update its Markdown/Canvas pair | [analyze-paper](../skills/analyze-paper/SKILL.md) owns that analysis and paired format; a report can cite existing authorized analysis without regenerating it |
| Maintain the internal project entry | [organize-project](../skills/organize-project/SKILL.md) owns PROJECT and its plan/navigation; project presentations may draw from that entry without replacing it |
| Construct topic-library navigation, literature or technical-route trees | [build-literature-tree](../skills/build-literature-tree/SKILL.md) owns these knowledge artifacts |
| Prepare a recommendation Reading Report | [recommend-papers](../skills/recommend-papers/SKILL.md) owns paper information, complete abstract and project-homepage links; this is outside the report system |

A knowledge note, paper analysis, PROJECT or README keeps its existing purpose and
format unless the current task explicitly requests a report derived from it. An
experiment archive retains its recorded execution facts; preparing a report does
not launch, clean up, promote, classify or alter those experiments. Importance of
an experiment remains a human decision. A report request is not an import,
record-maintenance or source-acquisition authorization.

## Shared content and writing

For original explanatory prose in a report, load the
[content-and-style Skill](../skills/content-and-style/SKILL.md). Its linked shared
contract holds explanation quality, Chinese prose, typography and human-review
requirements. Read the applicable sections for the selected edit and medium;
these requirements are not duplicated in this contract.

The report's communication purpose determines which evidence to present and how
much explanation is needed. Preserve the conditions and meaning needed to read
its results when adapting detailed material into slides or captions. The source
archive and existing detailed explanations remain available through usable links.
The shared prose rules do not rewrite verbatim quotations or impose report sections
on summaries, cards or compact Canvas nodes.

## Medium and actual delivery

The conversation normally specifies the medium. Use that medium and its available
native authoring/export capability, together with any explicitly selected template.
Apply the shared contract's
[medium and typography requirements](content-and-style.md#medium-and-typography)
when font controls or reader/export styles are in scope. Do not require a person to
design ordinary spacing, hierarchy or figure placement through a separate form.

When a file is requested, return a usable file of that actual format at the
authorized destination. Renaming plain text to a requested extension or returning
only a proposed outline is incomplete. Inspect the actual rendered result where
the format supports it. If a necessary capability or material is unavailable,
report the affected limitation and provide the safe result the task supports;
do not silently substitute a different medium or claim an unverified rendering.

Use the current authorized destination and existing update protections. Preserve
source originals, human notes and authoritative records. A conflicting existing
file is not silently overwritten, and a saved report does not update an experiment
index, project plan or knowledge registry by implication.

## Delivery and review

Follow the shared contract's
[delivery and review requirements](content-and-style.md#delivery-and-review).
Give the person the actual report, its location or opening method, and the specific
aspects that need human assessment. The person reviews the content and appearance;
revise according to their feedback and deliver again within the task's permissions.
Record acceptance only after explicit confirmation. Structural checks, source
support, rendered appearance and human acceptance remain separate results.
