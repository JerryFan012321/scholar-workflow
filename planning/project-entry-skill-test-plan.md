## 最小输入集（待单独准备）

准备三个新的小合成项目目录，每个均有自己的原始输入清单。raw fixture 应先于候选输出落盘，
由另一任务按下表准备；不能从未来生成的 PROJECT、产品 validator 或既有展示样张反推输入。
所有时间、实验状态和数值明确是合成声明，不是执行证明。具体样本数只用于该测试，不成为通用模板要求。

| 场景 | 最少原始输入 | 要验证的差异 |
|---|---|---|
| `complete-inline` 正例 | 含人写段落的对外 README；明确目标与当前状态声明；可静态核对调用关系的两个代码文件、一个配置；两条选定 Run 及其 Attempt/Artifact 记录；一篇论文的资料笔记、分析与 Canvas 显式引用；没有另立 SCHEDULE 的计划声明 | 一份可独立阅读的内部 PROJECT：直接导航、证据状态、静态代码关系、全部所选实验入口，以及一份内联权威计划；不复制论文正文、不重跑实验 |
| `sparse-external-plan` 缺失/不确定反例 | README 与独立 SCHEDULE；已有代码文件但一条仅被文档声称的模块关系；一个缺失配置/成果入口；一条成功重试记录；论文分析或 Canvas 缺失；阅读器未查询；备份只声明 pending；一个无日期里程碑 | 清楚暴露缺失与未核验，不编代码关系、日期、成果或阅读器可用性；PROJECT 只摘要并指向 SCHEDULE，不维护第二份详细计划 |
| `preservation-conflict` 守恒/权限反例 | 已有人写 PROJECT 和 README；PROJECT 与 SCHEDULE 中互相冲突的详细计划，未指定哪份权威；已有论文单元；用户只要求预览整理建议 | 保留全部输入字节，展示冲突和待确认项；只交付明确标识的会话/独立候选，不覆盖人写文件、不擅自选择计划权威或改 Git/发布配置 |

可复用 `tests/fixtures/experiment-review/project` 的记录作为只读基础：只能在新 fixture 中
制作显式合成副本，不能编辑原目录，也不能把旧审阅报告直接当新入口的事实或预期。
新 fixture 的代码/配置/引用和计划须有独立手写来源；入口脚本只供静态阅读，不执行。

至少一个场景应保留同一 Run 的失败、成功和 replay/retry 历史，以验证 Attempt 不被当成独立 Run
或独立重复实验。无需为此再做真实实验，也不要求每份项目恰有两个 Run。

## 后续测试说明（本轮未执行）

对象限上述新合成目录及明确候选输出位置。准备者先列原始文件、选定 Run/Attempt/Artifact、
论文引用身份与实际路径、计划权威/冲突、缺失项，并记录输入字节基线；报告哪些文件本就不存在。
测试不扫描目录外资料、不调用 Hub、Zotero、Obsidian、cmux、网络或源码程序。

候选交付应包括：内部 PROJECT 的人类可读候选、必要的唯一 SCHEDULE 或其引用、独立核对结果；
不得通过生成一个新前端或新的权威清单替代该入口。具体视觉排版留待候选审阅，不将现有 HTML
草图或某个示例的表格/数值数量固定为通用模板。

后续独立核对直接比较 raw fixture、`EXPECTED.md` 与实际输出：

1. 核对目标、核验日期及每项当前状态的依据；执行状态、静态检查、输入声明、未查询分别可辨。
2. 逐一解析所选代码、配置、Run、Attempt、Artifact、论文资料/分析/Canvas 入口，确认目标文件
   或诚实的缺失状态；不以同名文件证明资料身份，不实际启动阅读器。
3. 对照少量实际代码语句核对图中的关系；仅文档声明的关系不得被画成已证实调用或执行数据流。
4. 核对 Run 与 Attempt 的层级、全部所选记录的状态，以及 retry/replay 非独立实验；成功记录
   不冒称实际执行、复现通过、科学提升或备份已验证。
5. 核对计划只存在一份权威细节；外置方案中的 PROJECT 是摘要/导航，日期缺失和权威冲突均可见。
6. 守恒 README、人写 PROJECT、原论文单元、输入实验记录和其他原文件；核对实际新增/修改范围。
   没有授权写入的反例必须零业务写入。调用记录中不得出现初始化、训练/评估、迁移、复制论文、
   Git 写入、发布/安装或启动服务。

自动内容/路径核对、人工可读性与安装态验收分别记结果。测试失败保留输入和失败观察，不能改
原始资料来适配候选，也不能用后补预期覆盖先行预期。

## 人工评鉴交接

候选出现后，在会话中给出精确打开位置与操作：在 VS Code 阅读内部 PROJECT，点击代码/配置、
所选实验和论文各入口，并检查计划链接。让用户判断项目是否一眼可理解、入口是否直接、状态与
缺失是否清楚、模块图是否诚实、计划是否不重复；未明确确认前标为待人工评鉴。

本轮不要求用户评鉴不存在的文件，不以规划文件准备完毕宣布 skill 完成。若之后需要验证已安装
插件的触发/打包能力，再走独立 hotfix 发布安装流程；不能将本轮场景准备冒充正常安装验收。
