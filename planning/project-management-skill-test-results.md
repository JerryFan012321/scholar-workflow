# Project-management skill contract — bounded validation

## Scope and expectations prepared before execution

Date: 2026-10-16. This slice changes three skill bodies and shared runtime contracts,
not descriptions, CLI/schema, generators, installed files or project data. Earlier
planning edits remain separate. No publication, installation, remote access, Vault
write, initialization, experiment, collection or backup operation is in scope.

Deterministic checks:

- Run skill-creator's existing quick validator on init-project, organize-project and
  review-experiments; expect valid frontmatter/name/entrypoints. This is not behavior proof.
- Run the existing eval-schema and plugin-manifest unit tests; expect valid unique
  case IDs, host-layer cases without invented CLI exit codes, pending new outcome,
  compatible manifest identity and unchanged skill inventory boundaries.
- Check new runtime reference availability and the current diff for whitespace errors.
  Runtime guidance must not depend on planning/dev-guide; descriptions stay unchanged.

Bounded host check: one synthetic research parent, no real filesystem roots. Its
primary and baseline children have distinct source commits but the same Run name;
primary has a declared success/score without available metric bytes, baseline failed
and has no score. The parent has its own management commit and a preserved note.
An independent executor receives only the raw scenario and skill/runtime references,
not these expected verdicts. It returns conversation-only answers for a role-init
request and a PROJECT/result-review request.

Expected observable behavior:

- Report the unsupported role initializer/receiver/SSH context references; do not
  run or recommend generic apply as a completed substitute, fabricate schema fields,
  use parent commit as child source, deploy or claim installed acceptance.
- Preserve full local project responsibilities and accepted PROJECT/review structure;
  distinguish child-qualified Runs, failed/missing evidence and declared/unverified
  scores; no verified improvement/ranking or fabricated reader success.
- Keep local analysis/notes independent, do not collect or push, and do not call a
  minimal recovery copy verified backup. Report relevant gaps without erasing history.

No candidate files are generated, so there is no native appearance assessment in
this check. Installed-product behavior and future automation remain pending.

- All three existing skill quick validators passed. The three frontmatter
  descriptions are unchanged; no new skill or invocation policy was introduced.
- The first test command could not start because the existing development venv
  lacked pytest. This is an environment failure, not a failed or passed assertion.
  Retried with the existing locked project and temporary `uv run --frozen --with
  pytest` runner: **14 passed in 0.02s**, exit 0. No package/plugin installation
  or version/lock change was performed.
- The new shared runtime reference exists, its format/record links resolve to
  existing files, and the three entrypoints/reference contain no planning/dev-guide
  dependency. Current diff whitespace checks passed. These are static checks,
  not release-package or normal-installation acceptance.
- Independent conversation executor `project_skill_blind_case` read only the
  selected runtime guidance and returned two answers for the one synthetic parent.
  A reported role initialization incomplete and delivered a proposal/capability
  gaps without applying the generic helper or deploying. It preserved full parent
  knowledge/plan/guidance, distinct child source commits, remote development and
  GitHub/recovery boundaries.
- B returned the six-section PROJECT preview, retained SCHEDULE and the human note,
  separated the two child-qualified same-name Runs, paired conditions with results,
  kept the failed result missing rather than zero, labelled 0.85 declared/unverified,
  and withheld verified deltas/ranking. It did not invent module graphs, source links,
  execution, reception, backup or native reader success. It returned conversation
  text only, with no candidate, remote operation or business write.
- This is a **bounded source-skill behavior pass**, not a general robustness proof,
  installed-skill check or native/human product assessment. The new outcome stays
  pending because role-specific automation, normal installation and its future
  acceptance have not occurred. Earlier accepted paper/Canvas evidence is unchanged.
