## 结论

一个正式单元，一个主归属；多个领域或项目可以引用它。归属、主题分类、使用场景、
编辑工具是不同问题，不能因为加入另一个领域就复制或搬动正式分析。
项目集中展现它所使用的材料，而不是接管这些材料的存储和编辑权。

| 单元 | 主归属 | 其他容器持有什么 |
|---|---|---|
| 论文原 PDF、正式批注 | Zotero | 稳定论文/附件引用；不能维护第二份正式批注 |
| 通用论文分析、Canvas、证据图片、Scholar 阅读笔记 | 知识库中的论文包 | 引用整包或具体产物 |
| 跨论文比较、文献树、领域综述 | 对应领域的知识文档 | 对所用论文的引用和领域特定论述 |
| 代码、实施决策、项目特定方法说明 | 项目 | 项目资料清单中的选择和用途 |
| 配方、执行记录、原始结果、实验报告 | 项目的 Run/Attempt | 按实际实验身份引用报告/成果，不冒充论文复现 |

领域特定的解释、项目特定的改法不是第二份通用论文分析，可以分别拥有。
一张论文图片可以同时被该论文的 Markdown 与 Canvas 使用；这不是两个论文 owner。
ZotFlow 来源笔记仍保持独立 writer，不与 Scholar 分析或 Better Notes 共写文件。

## 实现缺口与最小顺序

1. **先核验正式定位。** 现有 `project-context` 只校验外部 ID 和阅读 URI 的语法，
   所有外部项仍为 `unverified`。首先从已登记 Source 的现有声明解析唯一正式对象，
   分别报告 owner 已解析、当前文件可用性、阅读器未验证。不要用一个“已通过”混淆三者，
   也不把 owner 解析当科学支持认证。原只读 overview 的无网络、无工具启动边界保持。
2. **在登记前查重。** 当前新论文登记只检查所选 Source 的 provider；需核对同一
   主机 registry 内已登记 Sources 的同一 Zotero 论文身份。冲突、不可核验或不可读声明
   不能静默选第一个或新建替代 owner。不扫任意磁盘、不按同名判断、不隐式合并旧身份。
3. **再补领域引用。** 当前多主题字段只是投影，Field 尚无正式资源引用登记。
   为已有资源增加多领域引用，不再调用新论文 owner 登记。具体字段与 schema 演进
   在这一切片单独确定；不提前修改 fields.yml 或发明已可用的 CLI 命令。

复用现有 registry、资源/产物声明与项目清单。汇编出来的 owner 查找结果是可重建视图，
不能成为独立权威台账；不另存论文正文、元数据或自动同步关系。
既有 schema 和读取接口尽量保持，知识核心不能反向依赖 Hub 服务。

## 移除、复制、迁移的不同结果

- 删除一个领域/项目引用，只删除该容器的选择，不动论文包、PDF 或实验。
- 显式复制成为独立内容，独立身份与演化；不暗中绑定同步或强制 provenance。
- 隔离复现可以保留便携身份，但只能进入指定隔离状态域，不自动加入生产 owner 集合。
- 改变正式 owner 的位置需要独立预览、CAS、链接处置和条件恢复，不夹带在普通更新里。
- 不强制增加首页、固定主题分类或把所有单元搬进一个总目录。

## 完整归属能力的后续验收范围（未执行）

每项手写预期先于实现；第二 Source 只用于明确的冲突/不可用用例，不复制真实论文。
下表是分切片的整体范围，不是当前只读定位已经实现的操作；当前57项合成预期仅由
knowledge-ownership-test-plan.md和tests/fixtures/knowledge-ownership/EXPECTED.md持有。
登记、引用增删、独立复制和owner迁移不因只读查验准备而成为可用能力。

| 输入与操作 | 预期结果与通过标准 |
|---|---|
| 同一正式资源被两项目、两 Field 引用 | 解析同一 owner；原件仍只有一份，引用分别拥有用途 |
| 移除其中一个引用 | 原论文包、另三个引用、PDF 与实验声明均不变 |
| 第二 Source 声明同一正式论文 owner | 返回可审阅冲突，拒绝登记，零内容/registry 写入 |
| owner 缺失、禁用、声明不可读 | 分别报告原因；不扫描补全、不回退到另一个审阅副本 |
| 正式 ID 配上陈旧或指向其他文件的 reader URI | owner 与阅读入口状态分开；不把 URI 当身份或认证正确打开 |
| 越界路径、symlink 或 CAS 改变 | 安全拒绝；不改原件或其他容器 |
| 独立复制/隔离复现 | 不抢占原 owner；普通引用删除不级联影响副本 |
| 已认可的分析包 | 正文、Canvas 完整 JSON、图片与基线保持，不重新渲染或分析 |

安装态只用当前 V-JEPA 2、test Vault 与一个模范项目，不迁移其他资料。实施前补齐
对应 hotfix 版本、源码/安装身份、实际入口、测试命令和输出位置；这份方案不是安装授权。
可见产物是一份清楚写出“正式存放位置、在哪些容器使用、为什么使用、不可用原因”的
资料清单；人工评鉴需在会话中明确打开方式和标准，再由用户评价导航与使用是否方便。
