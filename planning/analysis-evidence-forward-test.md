# 逐条证据呈现：独立合成行为测试

## 对象与边界

当前开发树与正常安装0.47.2的analyze-paper输出契约相同。V-JEPA2独立生成已经交付
结构合格成品，但逐条摘录覆盖、归因和强调不完整；原结果保持部分完成，不以本测试修正。

本测试只验证现有输出契约在短合成记录上的可执行性，不生成论文包，不验证整篇分析、
原生阅读器、知识归属、视觉效果或普遍one-shot可靠性。合成内容不冒充真实论文发现。
不增加运行期思考流程、自动语义评分或每个source span必须独立覆盖整条陈述的规则。

## 独立输入与预期

- 输入：`tests/fixtures/analysis_evidence_review/inputs.json`。
- 调用方预期：同目录`expected.json`。执行者不能读取该文件或本文。
- 使用正常安装0.47.2的SKILL及相关输出/证据契约，不提供V-JEPA2、旧IR、历史缺陷清单
  或本测试预期答案。执行者仅审查所给现有记录，返回JSON，不写文件或调用业务API。
- 一名新只读子代理、一次初始任务，无调用方追加指导；不是新的native安装验收对话。
- 测试前记录输入和预期hash；完成后核对未变。失败保留，不通过追加提示改答案。

## 操作与通过标准

1. 冻结八个record级输入及独立预期，记录当前安装身份。
2. 执行者按安装版契约返回每个record的`complete`或`incomplete`、理由及必要的最小修正
   建议；修正只限已有合成来源，不编造引文、删实质论述或写成品。
3. 调用方按独立预期比较状态与关键语义：缺失细节必须指出，分析不能冒充作者陈述，
   粗体必须突出本record的直接支持；正确的多span联合证据、已明确的分析推断和确实
   全句支持的整句强调不能误报。措辞不同不算失败，不用字面数字共现替代语义判断。
4. 检查工具轨迹的授权范围和输入/预期不变。静态JSON/schema检查与实际行为评价分开。

测试仅涉及开发fixture与结果回执，可能产生模型调用成本，无业务写入、发布安装或合并。
可见产物为本文的结果、fixture与单次返回记录；结果文件在执行结束后再创建。

## 后续发现：复合记录的来源容量

真实步骤提案暴露短例未覆盖的实现限制：v5也被v4每record三span约束收窄，而方法
总览要求步骤合写。现有Evidence基础最多八span。初步修复先测试继承容量，不改变
具名槽、分支、原文长度、字号或几何，也不把任何上限作为删内容的理由。

执行前预期：新的独立合成测试分别给claim与point四/八个完整、独立物理页来源。
v5的model及JSON Schema应接受并原样保留；渲染/校验应保留所有折叠摘录、精确强调、
来源入口与正文反链，实际几何仍须合格。v4三span保留、四span继续拒绝；基础九span
仍按既有边界拒绝。先红测，再同步最小model/schema修正；定向来源/quote/五分支/
批次/更新回归和完整unit/contract用于防止兼容性变更，不用真实论文作调试输入。
当前真实候选、正式资料、安装版和既有批次/修复预算均不得变化。开发修正不等于安装
或真实缺口已关闭；需要实际更新前另核安装能力与用户授权。

红测实际为12 failed/4 passed：v5的claim/point四/八span在model与Schema均被旧三span
上限拒绝，v4兼容及基础九span拒绝正例通过。分离v4约束后，model/Schema与渲染的
结构校验均正常；四个新断言先遗漏原文句点的Markdown转义，修正测试期望（不改
产品转义）后16 passed。所有折叠摘录、精确强调、来源URI和正文反链保留。
初步修复完整unit/contract为3297 passed、11既有warnings。这只对应3→8中间版本，
不是下述修正的结果。源码候选0.47.3、安装仍0.47.2；不用源码输出更新论文。

### 第二轮输入与预期：保留真实所需来源，不换一个数量配额

继续核对完整步骤发现：保留原图1摘录并补明确的特征预测原句会有第九span，不增加
物理页；未证明九是最少数量，不以压缩引文为过关条件。v5应取消record来源数配额，
不是3改8或9；旧v1–v3最多八span、v4最多三span按版本保留。

执行前固定以下独立合成检查，全部只在开发树及pytest临时目录，无Vault、Zotero、
安装或远端写入：

- model/Schema：claim和point各含3/4/8/9/12/20个合法span，全保留且往返不变。
- 渲染：3/4/8/9/12来源的折叠原句、精确粗体、逐页入口和精确正文反链全保留；
  若实际高度超过420，保持内容并报告真实几何失败，不放宽高度或减少来源。
- 旧格式：v1–v3八span通过、九拒绝（v1没有point）；v4三通过，4/8/9拒绝。
- 在最后一段放坏attachment/page/hash、超长quote或过多强调片段，model/Schema
  都应拒绝；强调不属于原句由model语义校验拒绝，不要求Schema推导子串关系。
- 来源很多且实际框高超限时仍拒绝conformance；不把无数量配额等同可读性通过。
- 同页12段来源及显式Canvas链接去重：正文摘录和IR仍保留12段，Canvas只合并重复
  阅读入口，不把段落证据去重。40短链接实测仍可安全排下，不能把数量当失败标准；
  超高负例改用200独立页来源的完整review候选，先断言实际高度>420再核失败。
- 临时目录内公开batch-run/check-bundle：12段point来源进入baseline且包合格；
  相同请求幂等，改变最后一段页码后复用batch必须冲突，已有stage字节不变。

先对3→8中间实现运行新预期，记录红测，再做最小版本化model/Schema修正。随后
运行来源/quote/五分支/几何/批次/更新定向回归、完整unit/contract及Ruff。开发结果
不能关闭新候选的科学支持、原生/人工或canonical门禁。
