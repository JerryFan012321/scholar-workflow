# 推荐页面使用体验审查

日期：2026-11-10。范围为当前未发布0.52.0候选。本文保留改版前的调研与审查依据；
用户要求开始修改后，最小改版已实施，实际检查与未完成项见
[UX实施结果](recommendation-ux-results.md)。下文“当前问题／待实施”描述调研时状态，
不覆盖结果文档；自动检查仍不代替人工使用体验验收。

## 当前阻碍

1. 列表只提供查看详情，原文、稍后看、忽略等高频动作需要进入详情。
2. 详情没有上一条/下一条，连续处理需要反复关闭、找下一项、重新打开。
3. 五组筛选、处理状态、排序及说明同时展示，窄窗口首屏阅读面积不足。
4. 标签、来源、摘要、审阅、评价、入库等职责虽已拆开，用户仍须理解多个状态和控件。
5. 同对象更新重建DOM，焦点/滚动保持不完整；换对象没有明确重置阅读位置。
   评价/上下文草稿也尚未覆盖刷新、关闭后的恢复。

## 成熟产品可借鉴之处

- [Hugging Face Trending Papers](https://huggingface.co/papers/trending)：列表保留标题、简短说明、
  作者/时间和原始计数，并提供GitHub/arXiv直接入口。我们可保留紧凑信息流并加入直接原文入口，
  完整翻译继续在阅读面展示，不在列表堆完整摘要。
- [alphaXiv Explore](https://www.alphaxiv.org/)：实际首页聚合工作介绍、作者/机构、计数和内容链接。
  本项目不照搬社交/关注/会议等完整功能，只参考内容优先的信息层级。
- [Linear Triage](https://linear.app/docs/triage)：把接收、拒绝、稍后处理组织为连续审阅动作，并有快捷键。
  适合借鉴其连续处理方式，不迁入工单状态模型。
- [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：
  低频/高级功能延后展示，同时明确高频功能应在首层可见。设置移走后，还需把阅读和高频动作放回易达位置。

这些来源支持各自的功能事实。下列布局和优先级是针对本项目的设计判断，未声称产品方验证了本方案。

## 建议的最小改版

| 优先级 | 调整 | 可观察效果 |
|---|---|---|
| 1 | 卡片增加原文与稍后看入口，其他低频动作收进更多 | 浏览列表时直接读原文/留待后读 |
| 1 | 阅读面提供上一条/下一条、当前位置及稳定操作栏 | 连续阅读不再反复关闭详情 |
| 1 | 首页保留搜索、处理状态与排序，次要筛选折叠并显示已选条件 | 窄窗口首屏仍以推荐内容为主 |
| 2 | 热度有值时用一行数字；缺失时短提示，技术诊断按需展开 | 缺失数据不占大块阅读空间 |
| 2 | 个人评价轻量编辑；可撤销的选择提供即时反馈，实际写库仍明确预览与确认 | 减少表单操作，同时不扩大Zotero写入权限 |
| 2 | 同对象更新保持滚动/焦点，切换对象回顶部；刷新前保留会话草稿 | 保存和返回不打断阅读或丢输入 |

建议先用既有4个合成候选走一遍真实任务：打开原文、标稍后、评价、处理下一条、返回原位置，
展示点击次数、焦点和滚动结果。只调整该对象，不增加真实推荐/全库扫描，也不重做科学分析。
需要人工确认是否顺手；自动DOM和接口检查仅证明相应行为约束。

## 设置页面与按钮专项调研

日期：2026-11-10。用户追加要求。以下是公开产品/设计系统资料与当前源码的对照，
属于待实施设计建议；本轮没有改UI代码、重跑测试、改数据、发布安装或切换服务。

### 参考与适用范围

- [VS Code Settings](https://code.visualstudio.com/docs/configure/settings)：按类别查找，
  支持搜索、查看已修改项、直接定位某项与立即应用设置。适合参考清晰的分类/适用范围/恢复入口；
  当前只有三组页面，不需要复制它的全套设置搜索和复杂过滤。长文本也不机械采用立即生效。
- [Atlassian Button](https://atlassian.design/components/button/usage)：按钮文字描述行为，
  每个操作区突出一个主操作，次操作降低视觉权重，普通按钮不必都加图标。
- [Fluent Button](https://fluent2.microsoft.design/components/web/react/core/button/usage)：
  区分导航链接、动作按钮、菜单与立即生效的切换；禁用状态需要说明不可用的原因/恢复方法。
- [Atlassian Link icon button](https://atlassian.design/components/button/link-icon-button/usage)：
  图标按钮需要清楚的名称/提示，图标应有通行含义。齿轮适合设置入口，保存/取消不必改成纯图标。
- [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)：
  WCAG2.2 AA规定一般指针目标至少24×24 CSS像素，并有间距等例外。当前33×33齿轮本身
  不能据此判为不达标；触屏舒适度仍可改进。建议常用控件采用约40–44像素点击区域，
  图标保持紧凑；该尺寸是本项目设计建议，不冒充最低合规阈值。

来源支持各自的组件事实；以下组织和文案是针对本项目的建议，不声称上述产品验证了本方案。

### 当前具体问题

1. `workspace.js`上下文保存后再次输入不会更新dirty状态，仍可能显示“上下文已保存”；
   任何有新修改的编辑器都应重新显示“未保存修改”。
2. 上下文的重新载入会直接替换textarea。来源要求编辑已有丢弃确认，两种编辑器行为不一致。
3. 齿轮实际上是页面导航，却使用aria-expanded表示可展开，再次点击不关闭；
   切页未明确定位标题/记录页面历史，浏览器返回和键盘导航体验不完整。
4. 已登记来源、账号已连接、任务实际已执行是不同状态；界面不能靠“已收录”让人猜测可用性。
   来源要求、共享上下文、入库回执也应各用一句话说明适用范围。
5. 多个小文字按钮和齿轮点击盒偏紧，保存、刷新、丢弃等权重/作用范围需要更一致。

### 建议的设置结构

保留一个齿轮入口和“返回推荐”，进入后呈现三个清楚的分组，不把设置重新放回信息流：

| 分组 | 首先显示 | 按需显示 |
|---|---|---|
| 推荐源 | 来源名称、登记/连接状态、编辑推荐要求 | MCP/API接入信息、能力说明、技术诊断 |
| 推荐上下文 | 当前关注点、需要延续的判断、最近维护者和时间 | 历史版本和技术标识；不展示模型执行控制 |
| 入库记录 | 紧凑记录、状态、时间及查询 | 单条分类、完整回执和失败详情 |

来源要求继续由任务显式选用；共享上下文供外部agent延续判断；保存任何一项都不启动agent或模型。
设置页进入/返回保留原推荐筛选、选中内容与滚动位置。宽屏可用稳定的局部分组导航，
窄屏保证能换行/选择且不挤压内容；具体采用侧栏还是标签由单对象可见原型比较决定。

### 按钮与保存状态约定（待实施）

| 场景 | 推荐交互 |
|---|---|
| 尚无修改 | 显示已保存状态；保存不强调，说明没有待保存修改 |
| 有未保存修改 | 突出“保存修改”；次操作“取消修改” |
| 正在保存 | 原按钮位置显示“保存中…”并防重复提交，不跳页或清空输入 |
| 保存成功 | 就地显示“已保存”和维护时间；继续输入后恢复未保存状态 |
| 保存失败 | 原输入保留，在对应区域说明失败并提供重试 |
| 其他agent/页面已改同一内容 | 保留当前草稿，可查看最新版后处理；不直接覆盖 |
| 放弃草稿/恢复版本 | 明确作用对象，放到更多/恢复区域；仅有待丢弃修改时确认 |
| 查看外部资料 | 使用清楚的链接，如“打开原文”“官方文档”，与本地写操作区分 |
| 真实Zotero写入 | 写明书目范围、目标分类，继续保留预览与明确确认 |

简单、可撤销且真实支持立即生效的开关可以即时保存；推荐要求和长期上下文是长文本，
本轮建议保留显式保存和草稿。实际功能尚不支持时，不摆放无效开关或暗示已经连接/运行。

图标采用统一风格；纯图标入口具有可见提示和可访问名称。设置导航、按钮、textarea和链接
保持明显键盘焦点，触屏扩大点击盒并留间距。颜色辅助表达主次/危险程度，同时保留文字说明。

### 下一版的人工检查场景

同一test对象完成：齿轮进入→找到一项要求→编辑并保存→再编辑时准确提示未保存→
切换分组返回仍有草稿→放弃或解决合成冲突→返回原阅读位置。另用键盘和窄窗口检查。
展示实际操作和反馈后由用户评鉴；这批调研结论本身不记为功能已实现或体验通过。
