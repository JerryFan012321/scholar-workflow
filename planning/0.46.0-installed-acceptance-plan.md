# 0.46.0 安装后单项目验收准备

本文件是待执行方案，不是安装/发布回执，也不批准真实服务器或正式资料写入。
候选批次：管理身份/双角色初始化、父子登记、分层实验接收与读取、版本更新恢复、
execution-code声明定位，以及本地代码恢复材料。原论文/Canvas格式及有效人工验收保持。

## 前置条件和对象

- 用户明确授权整批提交、正式发布、正常安装和test单对象验收；不由目标续行推导授权。
- 正式安装后固定source/runtime SHA、PATH CLI和包版本、双manifest及实际plugin cache；
  核对固定发行文件，不从源码目录、editable安装或临时venv执行产品验收。
- 唯一可见对象在已知`test` Vault内的独立候选目录；先读取该Vault与Git现状，不清理或
  改写既有样张。项目文档以VS Code为主要阅读器，test Vault只作隔离存放，不代替VS Code验收。
- 原始输入/预期和结果分开保存；一个合成总项目、一个合成child、两个Run。
  child输入在隔离输入区，仅代表可访问执行档案，不冒充已部署的远端机器。
- 不登记正式Source/Field，不创建论文owner，不调用Zotero，不连接真实服务器/推送项目Git，
  不开Hub或切换服务；不合并main。

## 预先确定的输入

| 输入 | 内容与独立预期 |
|---|---|
| Parent/child | 不同UUIDv4，child明确指向parent，primary角色；登记前后均保留原始声明 |
| 本地研究管理 | PROJECT六节，唯一内嵌计划、项目知识和规则/skills位置；不把空骨架称为完整业务正文 |
| 两个Run | baseline与variant，数据版本/split、seed、环境、评价协议相同；唯一配置差异为合成参数`feature_enabled`从false改为true。两个Run固定各自真实合成源码提交和配方 |
| 合成结果 | baseline示例分数0.60、variant为0.65，统一明确标为合成输入，非真实实验或性能优势；不指定真实论文/任务指标 |
| 完整历史 | 所选Run中含planned/running/succeeded/failed/interrupted五状态；保留时间、退出码、Target和配置快照，不能只展示成功记录 |
| 本地分析 | 预置一段手工标识的notes/report，接收、更新、回滚后字节不变 |
| 更新故障 | 固定的一次合法running→succeeded增量；在受控测试边界模拟中断，再用明确commit或rollback恢复，不运行训练进程 |
| 代码包 | 两个真实合成本地Git提交、自包含bundle；覆盖两个Run源码提交。不得查总项目HEAD代替；同内容留存一次，补查只加coverage |

## 操作、标准和可见结果

1. 用实际安装helper在新空根初始化两种角色，核对独立身份/Git与完整parent表面；
   不转换旧项目，不生成第二份计划。
2. 用安装CLI预览并显式登记child；接收两个Run并重复接收一次。核对原commit/全部状态、
   child限定路径、同内容幂等及本地分析守恒。保存原始命令/结果，失败不伪造收据。
3. 用安装collected读取本地资料；源child暂不可达时仍能只读核验。条件和结果同表，
   缺失/无效记录可见。该导航表不等于已完成科学比较。
4. 通过实际安装skill按PROJECT/experiment-review契约生成候选正文。两个Run的共同条件、
   唯一差异、结果和对应证据放在同一行/同一张比较表，合成标识明显；不复制知识库四树。
5. 显式update-plan/update-run与local-only recovery-plan/recover-update验证一次中断恢复。
   字节守恒、pending失败关闭及最终所选版本有真实回执；普通源码单测不冒充这次安装证据。
6. 显式code-recovery-plan/retain-code后重复执行，核对单份bundle、coverage、冲突保护与
   backup_state未验证；不是远端采集、代码恢复演练或verified backup。
7. 代码引用只检查execution-code及所选合成Target/ledger的声明位置；远端身份、SSH配置、
   访问、commit和原生Remote-SSH打开保持未核验，不制造可点击成功的假入口。

最终交付一个候选PROJECT、一个实验比较报告和独立验收表/原始回执；机器记录留在其
归属目录，不塞入人类正文。文件清单、输入摘要和Git差异另存验收记录，不重复生成多个样张。

## 会话中必须明确的人工评鉴

执行完成后，在会话提供确切PROJECT和报告路径及VS Code打开方法，指出状态、计划、
实验条件/结果和资料入口的位置。请用户评判是否一眼看清“做什么、进展如何、两个配置
哪里一样/不一样、结果对应什么证据”，链接/图形是否正常、是否有冗余机器文字。
未明确确认前标为待人工评鉴；合成样例、打开回执或自动测试都不能替代。

这项验收不关闭真实远端部署、自动源码采集、论文完整科学证据、其他模范Vault待评项、
WI-041备份或整个G17；它只证明这一安装批次在一个合成研究项目中的可观察行为。
