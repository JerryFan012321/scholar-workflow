## 已确认的对象关系与操作含义

### 实验边界与子项目

一个实验应能独立说明要回答的问题、比较目的或待验证主张，以及怎样判断结果。实验之间的实质区别在这些研究目标上；
配置文件、启动命令、测量指标或输出文件的数量本身不决定实验数量。
同一比较目的下的 baseline、variant、参数条件可以共同属于一个实验；补测遗漏指标、修正计算错误、完善解释与展示通常留在原实验。
独立的效率问题、机制验证或新的研究主张可以另立实验，具体边界结合研究安排和任务授权判断，不按固定参数差异机械划分，也不为普通组织调整逐次增设审批。

同一实验可同时包含多个配方，每个配方及其具体版本对应一组或多组结果。配方之间可以有训练、评测、整理等依赖，
也可以是同一问题下不同 baseline／variant 的并列方案；实验的 changelog 记录这些方案及其结果如何演变。
现有运行契约“科学配方变化时建立新 Run”保护的是已记录配方与结果的对应关系，不能据此认定要新建一个研究实验。
当前 RunRecord 固定一套配方，尚缺上述持续实验层的明确归属及操作；保留旧 Run 的哪些事实、如何归入实验，留待兼容设计，
不直接把 Run 当成 Experiment，也不把一个配方、一次执行、一个结果组强制设为一一对应。

子项目是实验组及其工作上下文，也仍是项目。某基线复现子项目可以含复现、对齐和差异验证等实验；
主子项目可以组织论文所需的主实验、比较、消融和其他验证。既有代码、配置、Git、原生运行入口、共享资产和上下文功能保留，
这里只调整实验组织、配方与结果管理和相应状态登记，不将子项目退化成结果文件夹，也不恢复本地开发远端代码的旧方式。

### 原 Attempt 的职责拆分

- 实验的修改原因、修改内容及对结果／结论的影响进入 changelog；它不承担逐条终端日志的职责。
- 主干代码、实验脚本、实际配置、输入和执行方法进入配方管理。
- 模型、测量数据、图片和表格等归实验结果；一个实验可以有多个结果，来自不同时间的执行或补测。
- 开始／结束、执行位置、是否完成及必要异常等事实保留为轻量执行记录，不要求每次执行长期保存整套产物。

这不是给已有 Attempt 目录直接改名。现有记录怎样兼容、哪些事实必须留下、记录放在哪里，仍需后续设计。

### 配方与最小复现能力

配方随实验改进，连接实际使用的输入及资产、主干代码版本、实验专用脚本版本、有效配置、必要环境和执行方法。
配方包含复现所需的代码依据：实验专用代码／脚本可以随实验保存，共享主干代码和第三方实现明确引用其实际版本及调用方式。
只给超参数不足以构成配方，也不要求将全部依赖源码复制到每个配方目录；所声明复现范围需要的代码必须仍可取得。
共享主干代码与脚本可以只维护一份，但必须能取得实验实际使用的版本；必要的未提交改动也不能丢失。
复现范围要明确：从头训练、用已保留模型重新评测、重算统计或重画图需要的材料不同，不能互相冒充。
保留某个路径或代码提交编号本身不证明依赖仍可取得；具体如何校验与记录仍待填写。

当前结果对应实际生成它的配方版本。更新配方但尚未重跑时，不能将旧结果标成新配方结果。
阶段存档关联当时认可的配方与结果；后续配方变化不悄悄改写已存档结果的来源。发现旧计算有误后，撤下受影响的结果和结论，
在修订记录中说明纠正原因；不因曾经存档就继续信任错误结果，也不要求长期保留其完整文件。
配方、实验脚本和轻量结果记录由所属实验的 Git 仓库保存版本，共享实现保留自身版本来源；模型、图片、视频等大型资产不进入 Git。
大型资产保留可核对的版本、位置和用途，避免原地覆盖后仍沿用旧身份；这些记录不能冒充大文件副本或可恢复保证。
不要求每次修订复制主干代码、完整环境或输入数据；具体版本关联与物理目录未定。

### 子项目内多个实验仓库

用户已将前一版“一个子项目一个仓库”改为“每个实验一个仓库”：子项目保留项目职责和公共上下文，可以包含多个独立实验仓库。
实验仓库管理该实验自己的代码／脚本、配方／配置、轻量说明、结果索引和 changelog；同一实验的多配方继续共用一个仓库，
不再向每个配方拆仓库。子项目的共享主干实现可以继续在既有代码仓库维护，实验明确引用其版本，避免每个实验重复维护一套公共实现。
实验需要改动公共实现时，为它保留隔离的修改与确切版本，不在其他实验运行期间修改它们正在使用的代码位置。
上层资料或共享代码仓库不递归跟踪实验仓库内部内容；只保留实验入口、用途和必要版本引用，具体排除／登记方式由后续实现决定。
每次更新通过 Git 提交保存版本，提交说明指出改了什么；阶段存档引用相应提交及被认可的配方和结果。
Git 提交记录更新，实验 changelog 解释这些更新对研究的影响，阶段存档记录阶段决定；一次提交不自动构成阶段存档或对外发布。

配方的实际版本可由所属实验／仓库、Git 提交和配方在仓库内的位置定位；执行时的实际参数覆盖、共享代码版本和资产引用也须保留，
不能只记录一个提交号就省略真实输入。仓库其他内容更新不改变旧结果所属的配方版本，已有可信结果继续指向实际生成它的版本。

Git 内容保持轻量，模型／训练权重、数据集、大体积图像视频和结果、缓存及临时构建物留在跟踪范围外。
少量随说明维护的小图和轻量指标记录可纳入仓库；结合用途、单文件及总体体积、数量和更新方式判断，不按图片后缀一律排除。
仓库可保存重资产的定位和版本，不能把大型数据改成文本后当作轻量记录加入。
忽略规则、提交前范围／体积检查是可选落实办法，具体阈值与实现未定。已有被跟踪的大文件怎样退出 Git，留到旧项目整理时另行预览。
本地主项目保持自己的资料 Git，实验代码仓库留远端。新增实验仓库不自动上传 GitHub；已有仓库沿用明确的发布授权。
主子项目采用多个仓库后，哪些公共实现／实验仓库对外发布、怎样组合交付仍待确定，不因属于主子项目就推定全部可发布。
发布范围未定不妨碍内部实验管理；旧仓库拆分留待明确迁移步骤。

### 追加测量与结果更新

遗漏测量可以在原实验追加测量配置、更新配方并补跑必要步骤。已有结果足以补测时不必重新训练或执行全流程；
缺少必要输入时再重跑受影响阶段。修改训练、输入或评测口径造成的影响需记录，不能把条件不同的结果静默混为一次比较。
每次修改区分新增、替换和继续有效的结果。失效结果可以按明确范围清除重跑，不要求保存整套历史副本。
旧结果可信且仍有比较、分析或复现用途时可继续保留，包括可信的负结果；不以性能提升或符合预期作为可信条件。
局部计算出错只撤下受影响的测量、图表与结论，未受影响的可信材料可继续使用；已替换或清理时留下可理解的状态，
历史记录不冒称旧文件仍存在。恢复先前配方时也要核对其输入、条件和结果是否仍适用，不能只看版本新旧。

### 阶段存档与清理

存档为本阶段有意义的配方及其可信结果留下可追溯记录，并按已明确范围整理和清理。一个实验可以多次存档，再追加任务、修订配方并继续研究。
已有授权和保留约定能够覆盖时，由 agent 完成阶段操作；保留取舍未定、清理范围扩大或涉及必须人工评鉴的判断时，再与人确认。
实验没有完成全部原定任务，但人已经决定不再继续、且没有要求直接放弃或删除时，可以据此结束当前阶段并存档，
不必为满足原计划继续运行。记录实际做到哪一步、为什么停止、保留什么，以及哪些原定任务不再开展。
可信的负结果可以支持“这条路径在这些条件下不可行”；因资源、执行或研究安排而停止则如实说明原因，不虚构证伪结论。
暂时无人运行不等于已经决定结束，结束并存档也不等于已达成全部原目标。
每阶段明确实际完成或决定不再开展的范围、结论、配方和结果对应关系、保留材料及清理范围；后续修正旧结论时说明关系。
存档不默认复制整个实验目录，阶段记录也不要求每次创建完整结果快照。

保留范围按实际用途确定：最小复现能力、重要结果及必要原始结果数据、训练成果、可复用输入和资产、
可独立阅读的实验记录，以及确有用途的执行／诊断记录。它们是用途检查参考，不是每次实验必须填满的目录清单。
输入和共享资产复用，模型及执行重资产仍留远端；本次约定的实验／测量任务完成并形成可分析结果，或人提出要求时，由 agent 拉回所选材料。
实验结果记录用于说明条件、数据和判断；汇报 report／PPT 按交流用途另行制作，不作为实验记录、回传或导航更新的前置条件。

制作垃圾主要来自生成工具缺少临时文件生命周期，不能把这个问题全部归因于实验架构。
PPT 定稿交付、转由人直接编辑后，生成阶段的 `.build/` 可以整目录清理，最终 PPT 和必要原始材料继续保留；
这里讨论的 3DGS 渲染垃圾是得到图片之前的中间产物，不是渲染出的图片。
阶段存档时清理已经结束用途的中间物；后续实验、下一阶段或恢复执行仍需要的材料继续保留，并说明用途。
项目资产复用不足、数据与脚本不灵活、实验分散分别讨论，不因清理制作垃圾扩大成全面重构。
人能查到阶段成果、保留决定和处理情况；临时文件按已有授权、明确用途与范围处理，不要求逐文件选择或每阶段重新审批。
阶段操作由下述工作区功能统一组织，具体程序尚未实现；本轮没有清理任何实验文件。

### 保留选择怎样落实到实际流程

当前用途原则先沿用，具体例子随更多实验反馈改进，不要求现在建立覆盖所有领域的保留清单。
“落实到输出配置、目录和清理范围”指让已经作出的保留判断实际生效：

- 程序已有输出选项时，按需要选择测量数据、渲染结果、诊断输出及其粒度；没有相应选项时如实记录，不能假称已经控制输出。
- 将要保留的结果和生成过程临时物分开放置，或由明确文件清单区分；例如图像和必要逐样本测量属于所选结果，生成图像前的临时缓冲另列。
- 阶段存档时按已识别的临时目录／清单清理，并检查是否仍用于复现、下一阶段或其他消费者；不能仅凭扩展名或文件体积删除。

这些是已有用途决定的实施含义，尚未选择具体路径、配置键或清理命令，也不增加每次实验必填的固定目录。

## 已确认：配方与结果配对，以及实验改进的含义

### 归属与管理主体

远端工作区有目录实体，是本地主项目在服务器上的执行和共享资源范围；这里不是 cmux 的窗口工作区。

子项目的研究归属始终是本地主项目；工作区是部署与资源使用范围，不另立远端上级研究项目或主项目镜像。
同一个本地主项目可以使用多个远端工作区，不因此要求各服务器复制全部子项目和资源。

**本地主项目负责远端工作区的管理，项目中的人和 agent 执行具体操作；工作区本身不构成另一个管理主体。**
不设“远端主管”文件夹、独立管理项目或特殊常驻 agent。角色不绑定会话记忆，获得授权的项目 agent 可按 Skill 接手操作，
但仍遵守当前项目和资源范围；登记本身不授予服务器访问、运行、发布或删除权限。

本地主项目可以发起开发、补测、执行和资源维护要求，实际子项目代码开发仍在远端。
本地保留与子项目身份对应的管理资料、收到的结果、分析及明确选择的最简代码恢复材料，不保留日常开发的子项目源码副本。
远端保存实际执行依据、所选可信结果和仍有用途的重资产；本次约定的实验／测量任务完成并形成可分析结果，或人提出要求时，由 agent 拉回本地主项目。
本地主项目保留接收与核对职责，模型、原始不可读数据和尚未归档清理的中间产物不回传；回传不意味着实验已经阶段存档或获人工认可。
本地汇总状态注明来源和最近核对时间，未连接或未核对时不冒称实时；登记“已下载”或“已完成”不能替代文件、执行及接收核验。
登记负责定位，管理还包含读取实际状态、进行授权操作、更新所属记录及确认结果，不只填写清单。

### 主子项目的内容

主子项目承载自有方法的核心实现，保留核心代码与模块、实际运行入口、配置与配方，以及研究需要的主实验、比较、消融或其他验证。
它保存自己产生的模型和必要原始结果、图表、changelog 与阶段存档，具有技术／接口／使用说明、项目内规则和执行上下文。
实验种类按实际研究确定，不预设固定数量或要求全部具备。主子项目内按上述实验仓库和共享代码来源组织版本，既定发布边界继续有效。
其他基线的完整代码和资产留在各自子项目，主子项目引用所需结果和接口，本地主项目进行跨子项目分析；
“主”表示研究中的核心角色，不要求再保存一遍其他子项目的全部内容。

### 共享资源的使用边界

工作区登记是项目内共同可见的资源目录。主项目与各子项目的说明／agent 入口都能找到同一份登记，按任务查阅所需条目；
不把完整登记复制进每个实验，也不依赖某个 agent 的会话记忆。本地需要副本时由相关操作的 agent 更新，并注明远端核对时间。
“可见”指可以发现入口、读取登记并按既有权限使用资源，不代表本地一定有资源实物或已连上服务器。

- 例如已建立 conda 环境 `a`、`b`，登记名称、服务器与实际环境位置、Python／CUDA及关键包版本或完整环境清单入口、
  适用用途和最近检查情况。子项目按需选择，使用的实际环境仍记入配方。登记同名环境不能证明不同服务器的依赖完全相同。
- 新建、调整或移除共享环境／资源时，由执行该操作的人或 agent 同次更新相应登记；发现位置失效时标明，保留可理解的原因。
  登记只描述已有资源及其用法，不自动创建、升级或重建环境，不要求为了这份目录另建代码仓库。
- 已有环境按用途和兼容性直接选用。隔离、冻结或另建环境在依赖冲突、变更影响或复现要求需要时采用，不是登记资源的前置条件。
  修改共享环境时检查使用者并更新登记，配方保留实际使用情况；包缓存可复用，缓存命中不证明运行环境相同。
- 下载的原始模型、原始数据集优先在有权管理的服务器资源位置按明确版本复用；微调模型、处理后的数据集
  有自己的来源、生成配方和版本，不覆盖原件。跨服务器按需保留物理副本，不强求全机只有一份，也不默认全量同步。
- 索引记录资产身份／版本、来源、用途、实际位置与可用性；只有索引不等于已下载，某机有副本也不代表另一台可直接使用。
  实验配方引用所需版本，主机定位可独立变化。复用既有服务器台账与项目身份，不另建重复的服务器／凭据登记。
- 共享预处理结果、公共脚本和评测定义也可复用；需明确消费者和版本。第三方基线的独立代码环境不强行合并。
- 阶段存档清理本实验已结束用途的临时物；共享资产清理需检查其他使用者和仍须满足的复现用途，按下述工作区操作顺序落实，程序待实现。

共享资源可以实际位于工作区内，也可以通过索引引用有权使用的外部位置；目录归属不授予对整台服务器资源的控制权。
跨项目复用的资产不能由一个研究主项目独占管理或单独决定删除。模型微调、数据处理等产生的成果先记录所属实验与来源，
具有后续复用用途时可登记引用，不默认搬动或复制原文件。

### 工作区配置与说明的内容范围

工作区只保存供子项目定位资源、正确运行和了解文件边界的信息；总体计划、知识和跨实验分析留在本地主项目，
实验配方、结果与 changelog 留在所属子项目。

| 内容 | 配置／说明需要回答什么 |
|---|---|
| 工作区身份与归属 | 工作区名称、所属主项目身份和用途是什么 |
| 子项目入口 | 各子项目的身份、目录位置和角色是什么；详细信息从哪个子项目记录读取 |
| 共享资产定位 | 资产名称／身份、版本、实际路径或索引、准备情况是什么；仅有索引还是已经有可用文件 |
| 环境入口 | 已建环境的名称、所在服务器／实际位置、关键依赖特征、用途和检查情况；完整清单已有文件时直接引用 |
| 存储位置与使用边界 | 共享原件、可复用派生成果、子项目输出和临时文件分别存在哪里，哪些允许修改 |
| 操作说明 | 怎样使用共享资源、添加资源或环境版本、检查可用性，以及阶段清理应注意什么 |

载体按工作区规模选择：简单情况可在一份文档中说明归属、子项目和资源入口；已有登记直接引用，需要程序读取或条目较多时再拆配置／索引。
不预先要求配置、说明、索引各占一个文件。主项目及子项目链接实际入口，让任一获准 agent 或人都能查到资源。
具体名称与格式尚未选定；登记已有资源不需要另设资源管理项目。
数据划分、采样范围、预处理参数及实际使用的环境由实验配方记录，工作区不复制每个实验的条件。
服务器身份和凭据继续使用既有台账与授权方式，不在工作区配置中另存秘密信息。

### 工作区阶段存档

用户补充原话：

> 还有，工作区应该也可以进行阶段性存档，清除一些临时文件，就像之前所说的一样

工作区同样可以多次进行阶段性存档，范围依据当前任务和已有决定，由 agent 按上述存档约定完成整理与清理。
记录本阶段完成的工作、涉及的子项目／实验及其状态、保留的结果与配方入口、继续使用的共享资源，以及已清理的临时材料。
优先引用子项目和实验已有记录，不重新维护一套实验事实，也不因工作区存档复制整套代码、数据或结果。

清理包括工作区范围内已经完成用途、没有剩余依赖的临时构建、导出和传输暂存等文件。
对子项目内部临时物的清理沿用其阶段安排，不因上层存档越过活动任务、保留结果、最小复现能力或共享使用者的边界。
共享环境、模型原件、数据集及其他仍有用途的资产继续保留；索引引用的外部资源不能仅凭工作区存档一并清理。
存档记录反映实际保留与清理状态，不默认全量打包、回传范围扩张或关闭工作区，之后仍可继续下一阶段。

阶段存档与清理由工作区提供统一操作，可选一个实验、一个子项目或整个工作区为范围；
各层保留自己的研究记录，操作只引用这些记录。用户已将操作顺序和中断处理交给 agent 设计，下面作为拟实施流程，尚未形成程序能力。

| 顺序 | 操作 | 进入下一步的条件与中断状态 |
|---|---|---|
| 1 | 依据任务授权明确本阶段范围，列出保留配方、可信结果、必要资产和待清理临时物，检查活动任务与其他消费者 | 保留取舍未定或候选仍有用途时，先保留对应材料并补齐判断；已有明确约定不重复审批 |
| 2 | 保存阶段记录、配方版本和保留／清理清单，记录候选位置、文件版本或变更基线；轻量文件按所属仓库保存版本 | 记录保存成功后才进入清理。状态为“已存档，待清理”；保存失败仍为“未完成存档”，不能先删文件 |
| 3 | 清理已明确范围且没有变化、没有新使用者的临时物，逐项记录成功、跳过或失败 | 每项操作前记录意图，完成后记结果；不因某一项成功就标记全部完成，中断为“已存档，清理部分完成” |
| 4 | 核对保留材料仍可访问、引用有效及剩余清理项，更新实际处理结果与占用变化 | 全部符合计划才为“清理完成”；某项失败／待复核保留明细。本次结果回传状态另列，不用“完成”掩盖材料尚未收到 |

清理不生成整套恢复包。已登记的共享原件、保留结果、当前运行需要的文件和最小复现依赖不进入临时物删除清单。
路径须仍在已选操作范围内；发生路径替换、符号链接越界、候选内容改变或新增使用关系时跳过该项，重新核对受影响范围。
某份材料若只有完成传输后才可删除其源副本，则须先核对目标完整性；普通临时物留在远端按清理计划处理，不为清理而先回传一份。

恢复操作沿用同一阶段及其处理记录，只继续尚未完成且基线仍相符的事项，不重做已经确认的删除，不覆盖新的实验成果。
若中断发生在删除与记录成功之间，恢复时核对目标：已不存在就记为“已不存在，删除来源未确认”，不能编造操作归属或释放空间；
仍存在则重新检查身份和用途。发生变化的部分重新生成清理建议，其余已完成事项保留。
研究阶段状态、清理状态和本次结果回传状态分别呈现，例如“已存档；清理部分完成；所选结果回传中断”。
这份阶段记录不是备份，也不保证已清理的大型文件可恢复。具体记录格式和操作接口待实现，本轮没有执行实际存档或删除。

## 实验结果回传、远端查看与项目入口

### 已确认：agent 在本次任务完成或人提出要求时回传结果

用户纠正了前一版“文件持续自动同步”的解释。回传由负责实验的 agent 在本次约定的实验／测量任务完成并形成可分析结果，或收到人的要求后发起。
“完成”按本次约定的工作范围判断，不必等整个长期实验最终结束或阶段存档；一次命令退出本身不证明任务已经完成。
agent 通过 SSH 拉回对应材料，后续补测或修订产生新结果时，在对应任务收尾时更新。
人明确要求查看进行中的实验时，可以取回已经生成、可解释的部分结果，并说明尚未完成的范围；无需先做阶段存档。
回传范围包括图片、视频、整理好的测量数据、比较表和帮助理解结果的说明、实际条件及配方版本入口。
模型／权重、原始不可读数据、尚未归档清理的中间产物不回传。远端保留按后续用途判断，不回传本身不是删除理由。
文件可打开、格式受支持或体积小，都不能单独构成回传理由；材料应服务本次查看、比较或分析。
选哪些材料、是否只需远端查看及如何呈现，结合任务和人类／agent 意见灵活决定；已明确的任务和材料选择直接沿用。
有人参与时，agent 先说明建议查看的材料、建议形式及理由，再征询人类意见；人已明确指定的方式直接沿用。
无人参与时，agent 可在现有任务授权范围内自行选择，并简要留下选择及理由，不把无人回复记作人工批准。
此处自主选择针对材料查看与呈现，不扩大删除、覆盖或阶段存档的权限。HTTP 查看是可选方式，不要求每次建立网页服务。
下面的传输／查看工具仍是技术候选，尚未冻结回传格式或部署服务；不增加文件监听、定时扫描或后台同步进程。

| 内容 | 候选方式 | 需要继续确定的边界 |
|---|---|---|
| 实验概况、实际条件、配方版本、结果清单及其状态 | 随本次结果回传必要说明，按所属实验核对和更新 | 必需记录及映射；不单独轮询整个项目 |
| 本地分析需要的指标、整理好的数据、所选图表和视频 | agent 按本次选择通过 SSH 拉回，rsync 是传输候选 | 记录用途与预计文件量；核对实际收到的内容，不按后缀全量接收 |
| 暂时只需查看的图像、视频和已有结果页面 | 远端只读 HTTP 结果目录或已有查看器，经 SSH 转发在本地打开 | 查看目录、查看器、服务生命周期与入口；打开仍需传输所看内容，浏览器缓存不等于正式本地留存 |
| 模型、原始不可读数据、中间产物与其他执行重资产 | 实物留远端；必要时在结果说明中列定位和用途 | 远端保留和清理另按用途处理，不混入结果回传包 |

回传边界按以下规则落实，具体新接口尚未开发：

- 负责实验的 agent 选择符合任务的可分析材料，用传输工具拉取，核对完整性和实验／配方对应关系，再更新本地记录；
  不把发出传输命令当作已经收到结果。必要材料缺失时说明缺项，不能用一句远端路径代替交付。
- 拉取已经写完的确定文件版本，接收端校验后才替换已有的受管结果；不把仍在生成的文件当成完整成果。
  若用户要求部分结果，明确它的截止范围和完成程度。
- 断网或中断时记录本次已收到和未收到的材料；agent 恢复该次操作时续传／重试，不重复保存相同版本，也不因此建立常驻同步服务。
- 执行事实来自远端，本地分析、计划和人工笔记在本地维护。更新受管结果时保护本地独立内容；冲突明确报告，不按最后修改时间静默覆盖。
- 结果纠正、失效或移除时，由负责该工作的 agent 更新相应本地结果状态和逐级结论；替换／删除只作用于已明确的受管结果范围。
  远端目录变化不自动扩散成本地删除，连接失败更不能作为删除依据。
- `.git` 内部、缓存、模型、原始不可读数据、中间产物和整套源码不进入结果回传。明确选择的最简代码恢复材料作为单独任务处理。
  大体积可分析结果按用途选择完整材料或有明确范围的切片／统计，不用体积或格式代替判断，也不把切片冒充全集。

技术依据：rsync 的 `--files-from` 可读取明确文件清单，`--dry-run` 与 `--itemize-changes` 可预览变更；
VS Code Remote-SSH 已提供远端文件访问和端口转发。它们不负责科学有效性、资产身份或归属判断，这些仍由本项目记录和操作规则持有。
预览中的文件大小是预计涉及材料的体积，不能将 dry-run 的网络统计当成实际传输量。
HTTP 仅负责已选结果的读取，可复用现有工具；不据此恢复旧 Hub、建立新的实验事实源，或向网页暴露整个工作区。

### 已确认：各级结果入口与实验原因

保留当前内部项目入口、唯一详细计划、知识资料、Agent 上下文及模块关系等职责，当前情况和计划仍在前面。

各子项目和实验的结果入口沿用同一要求，逐级进入实际结果、图表和数据；每一级说明本层目的与下层工作的关系，
避免把完整实验说明逐层复制。比较条件、结果和判断在负责具体比较的文件内放在一起。

例如，主项目说明为什么需要某基线复现并链接其结果文件；该文件说明为什么做各项对齐或补测并链接具体实验结果；
实验说明再直接链接支持结论的测量表、图片或其他所选材料。示例表达导航关系，不固定层数，也不要求增建空目录或中间页。
每一层都链接实际存在的下一级文件，结果文件本身即可承担说明与导航。某项尚无结果时明确写出状态，不虚构结果入口。

这部分可由人或 agent 直接编辑 Markdown，不要求脚本生成、另建统一表格程序或先实现 VS Code Tasks。
产出或修订可分析结果及其记录的同一个 agent，从结果所属层级开始，沿实际归属逐级向上检查并更新，直到本地主项目最顶层的 PROJECT.md／实际总入口，
再报告本次工作完成。不以另行制作 report／PPT 为前提，不能只改直接上级或把其余上级留给另一个 agent 或人收尾。
各级维护对应的结果链接、实验原因、状态和受影响判断；不受本次结果影响的正文保持原样，不为表示已经检查而制造改动。
工作区按部署关系登记，不额外插成研究父级；若它的状态入口受到影响，同时更新。尚无结果时保留真实状态，已有结果不能因未做汇报而继续标为待生成。
结果被纠正、移除或路径改变也触发这项维护：上级不能继续以旧结果支持当前判断；历史记录可注明已失效，不伪造仍可打开的入口。
若权限、冲突或文件缺失导致某一级无法更新，明确列出未完成位置，不能以底层记录已经写出代替整项收尾。
这属于负责本次结果工作的 agent 的职责；另行制作的汇报也需维护其相关入口，不另设专门管理 agent，也不要求人再手工更新导航。
用户是否认可结果仍单独记录，不把 agent 完成整理当作人工验收。
原生 Tasks／终端只在实际执行、传输等操作需要时作为候选入口；具体样式与操作仍待实际样例审阅。

## 人类掌握流程、结论和数据：已明确的目标

精简产物不得以人失去实验控制和判断依据为代价。脱离聊天记录、代码和 agent 的临时记忆，
人应能看懂实验如何进行、实际使用哪些条件、数据如何得到、结论依据与局限，并决定下一步。
这约束最终交付和真实操作接口，不规定 agent 内部推理过程。

以下是为该目标提出的具体呈现与交接方案，尚未冻结新文件名或 schema：

| 时点 | 人应能掌握什么 | 建议的最小呈现 |
|---|---|---|
| 执行前 | 问题/目的、baseline与variant的共同条件和差异、输入数据范围、真实处理流程、预期测量和保存策略 | 现有实验记录中一份可独立阅读的实验说明；与真实config/launcher及已解析配置对应，不能只给hash或源码路径 |
| 执行中 | 当前步骤、已完成/未完成、实际参数或数据变化、错误/暂停/取消以及可采取的操作 | 在同一实验入口呈现已有执行状态和关键记录的链接，不每一步另造一份总结；声明状态不能假冒进程仍存活 |
| 执行后 | 实际比较条件、结果数据、图表、判定、证据与适用边界 | 条件与结果同处，多实验比较表保留名称、时间、目的、配置及共同/不同条件；正文解释指标回答什么、为何支持或不支持结论 |
| 继续研究 | 怎样重算统计、检查样本、重新比较和复现必要步骤 | 必要粒度的测量/结果数据、字段/单位/聚合口径、处理脚本/配置与来源；不仅有选中的图或一句远端路径 |

数据保留的关键区别：支持结论复核、误差/异常检查或后续分析的测量数据属于结果证据，
即使当前报告未画出也可能需要保留。缓存、重复渲染和逐步debug dump不能因统称“数据”而全留。
大体积证据需要明确登记、可访问的执行端保存，以及足够本地分析的可读切片/统计与其生成口径；
只写“远端有数据”不算完成交付。代表性样本不能冒充完整统计，未披露/未收到的范围应说明。

人类的可编辑/控制入口继续采用现有 Markdown、表格、config 和单一实际launcher等原生形式，
不新增前端。人可按实际权限调整配置、决定运行/暂停/继续、选择分析范围和重要实验。
具体入口以项目已有能力为准，缺少暂停/恢复能力时不得虚构按钮或命令。

整体验收应让人回答：这次到底改了什么？过程实际完成到哪？哪些数据支持什么结论？还有什么没验证？
必要证据保存和流程依赖完成后，才按已批准规则释放临时产物；不把“我选出了几张好图”当作完整性证明。
这是建议的验收问题，不引入逐文件人工审批或自动永久保留所有数据。

## 从源头需要确定的六组事项

### 1. 一次实验最小交付是什么

建议每次至少交代：要回答的问题、实际配置与数据/代码/环境身份、执行状态、关键结果及解释它所需的证据。
结果必须与比较条件放在一起，失败实验保存必要错误与诊断，不因失败伪造结果或保留所有调试流。
机器原始结果中有后续统计价值的，保留在适当的执行/数据位置；本地接收可读的统计、表图及计算口径。

待定：各类项目有哪些不同的最小结果要求，机器结果应保留到何种粒度，以及执行端负责多少通用结果整理。
不能制定全领域固定图数、固定样本数或以文件后缀代替用途判断。

### 2. 生成控制，而非生成后全量收集

建议执行前由实际 config/launcher 明确：最终结果、可选诊断、调试 dump、checkpoint 和缓存是否生成、采样/频率及存放位置。
不是每次实验都需要全部逐步张量、全部中间渲染或全部调试日志；但记录“已关闭/未生成”不能冒称已存在证据。
具体参数必须接入真实执行入口；Skill 口头要求不能替代程序开关。

待定：不同执行阶段的默认输出模式、允许覆盖方式、必要失败诊断及异常运行的临时加量规则。

### 3. 存放职责与去重

建议区分逻辑职责，目录名仍待确定：

| 类别 | 建议归属 | 本地分析端 |
|---|---|---|
| 实验登记、配置/数据/代码身份、必要执行记录 | Run/Attempt 档案 | 接收必要原始记录 |
| 可直接解释比较的指标、表格、有效图像/视频、必要日志 | 明确选择的结果 | 接收并用于分析，保留条件及来源 |
| 模型、优化器状态、执行所需大体积数组和完整预测 | 执行/数据端，按实际用途保留 | 记录身份、用途和位置，不按结果递归搬回 |
| 跨 Run 可复用的数据预处理/共享缓存 | 数据集/公共缓存权威位置 | 不在每个 Run 重复复制；既有 dataset 聚合契约继续适用 |
| 阶段临时文件、调试 dump | 隔离临时区 | 不混入正式回传结果 |
| 面向特定汇报的报告/PPT | 显式报告任务 | 复用实验来源，不另复制一套实验档案 |

不可直接阅读并不等于无价值。原始观测、唯一测量、重统计所需结果、唯一可恢复 checkpoint 等不能仅凭二进制格式删除。
数据集原件与生成中间结果分别判断。共享缓存的消费者不能只查某一个 Run。

### 4. 怎样决定保留与清理

建议每类可选输出能回答：由谁生成、谁要用、为什么保留、能否准确重建、何时不再需要、如何处置。
这些规则适合进入可编辑的项目执行配置；生成后的位置、大小、状态进入既有产物清单，避免另建重复事实源。

建议分工：用户批准项目规则之后，项目代码可按该规则自动清理确认属于自己的临时文件；未知用途、唯一副本、活动任务依赖及规则外数据需另行判断。
尚未批准任何默认保留天数、checkpoint 数量、大小阈值、删除规则或自动清理范围。
依赖完成、必要证据保存、活动任务/恢复依赖消除及可重建性核验，是建议的清理前置条件，不等于程序已经实现。

### 5. 回传和成果消费

建议所有新的父项目回传使用明确 include/defer 清单，逐项有用途，而非按目录镜像或按扩展名全收。
接收与回读检查仍以已实现的身份/哈希/版本契约为准；体积小也不应回传无用途的重复中间结果。
执行端提供稳定的所选版本，本地主动拉取；必要结果缺失显示不完整，不能靠一份“结果在远端”的报告关闭交付。

待定：选择清单由什么实际操作产生、怎样核对本地分析所需字段、哪些阶段及时交付，以及清单与生产配置的对应方式。
代码缺口：现有无清单 whole-Run 分支仍在；定案后需收紧新写入口，兼容旧档案读取。
原生传输仍服从明确范围；插件没有远端稳定导出器或自动 SSH 传输，不应提前宣传。

### 6. Skill、程序与旧项目接入

建议在单一共享 reference 中持有最终的产物职责及处置契约，项目执行 Skill 引用该契约和真实 config/launcher。
init-project/project-management 只暴露必要入口；review-experiments 继续只读；清理若实现，应有独立 plan/apply。
不要在每个 Skill 中复制同一套设计哲学，或把一个具体项目的产物清单复制为全领域模板。

是否进入“重要实验”由人类另判，不是这个闭环的自动评分或清理许可。

### 推荐组件与初始化

现状：init-project不自动创建推荐任务。已有稳定项目身份后，可projects enable建立项目内上下文入口，再tasks register登记一个或多个producer任务。AGENTS引用入口让后续项目agent发现；外部宿主另行负责运行/定时。角色平权，不创建特殊常驻agent。

建议：初始化research-parent时显式交代推荐组件为“启用/暂不启用”，有已授权明确需求则直接接入；未选择不生成空任务、不启动推荐。以后可独立启用，不要求重新初始化项目。execution-child不默认复制父推荐上下文。此为建议，尚未改初始化器。

### Attempt与产物保留应独立

现状Attempt是同一固定配方的一次执行/重试，有小型状态与Target快照；不是保存整套模型/数据的要求。只重画图、修改说明或读取已有结果，不应因此伪造新的模型执行。

建议：登记所有实际执行及失败，但大体积产物在短期工作区与长期保留之间有显式决定。按Run展示并可展开Attempt，不把每次重试变成一整套重复材料或独立汇报。哪些结果必须保留以复核结论仍由实验交付要求决定。

### promotion与副本

现状promote从已可访问源复制单文件；同身份/同目的地/同内容可幂等返回，不是每次调用必然复制。它不是全局内容去重。实际输出、promoted副本、传输暂存、父接收文件、更新恢复包和报告内的再次复制可能累计。

建议优先减少复制环节：实际执行能直接写入规定的结果位置时不再为“正式保存”额外复制；报告和比较引用已有证据；稳定接收确认后仅按已批准规则回收本次暂存。跨机器为本地分析所需的一份结果与受控恢复材料可有合理副本，不能一概视为冗余。暂不先引入新对象存储/全局去重系统。

### 人类集中清点与留存选择

用户允许逐次确认，或能直观集中清点。建议采用“每次完成自动进入待审结果清单，人可逐条或批量决定”的方式，不强制每个Attempt都打断人，也不把未审自动当作永久保留。

建议清单展示：实验名称/目的、执行时间与状态、共同/不同条件、关键结果及图表、来源Attempt、当前本地/远端占用及可释放空间、保留用途/依赖、处理决定。按实际可核验值展示；文件大小之和不是去重后物理占用，未知不能填0。

可讨论的决定：保留必要结果、保留明确选定范围、暂缓决定、不保留可选大产物。重要实验标记仍独立由人决定。每个动作的实际文件范围、必要证据与不可撤销影响需明确；不是一句“不重要”就删整次实验。

未审期间应有项目选定的临时预算/容量告警，必要时停止继续产生同类可选输出；不能因用户没看清单而静默删除唯一证据。期限、预算与处置细则待定，不预设数字。

现有已登记/已接收证据受hash与版本保护；不能直接删除文件再让旧档案冒称完整。正式释放需要与记录状态、引用/依赖及恢复策略相容的独立预览/确认路径，该功能尚未实现。

## 2026-11-14补充：先探明产物，再通过实物选择制定规则

用户原话：

已明确的方向：输出粒度要控制，保留与清理依据用途；先查实际全流程产物，用受控smoke test观察，再由人选择有分析价值的结果；模型等执行重资产保留远端，不随本地分析结果搬回。具体清单、配置/schema、保留期限与清理授权尚未冻结。

### 提议的实际接入流程

1. 读取真实config/launcher，列阶段、写入位置、输出开关及已知条件分支；不先假定几个固定产物。
2. 准备单个有代表性的受控smoke test：沿真实执行路径缩小样本/规模，尽可能覆盖数据准备、执行、评估及导出。预先说明输入、预算、预期可见产物和影响范围；它不证明正式指标。
3. 按阶段清点实际产物：路径/归属、大小或序列规模、内容示例、字段/单位、消费者、能否重算、本地或远端，以及在本次smoke中是否实际出现。临时生成随后被删的文件需要结合阶段写入/日志观察，最终目录列表不能冒充完整过程追踪。
4. 明确区分“已观察”“代码/配置表明会产生但未触发”“尚未知”。短跑未到checkpoint周期、完整验证或失败分支时，不宣称全流程已覆盖；必要时只补验证该阶段的最小测试。
5. 向人展示结果样例和一份紧凑清单，由人选择本地分析材料、远端保留材料，以及可关闭或临时保留的内容。按产物组展示避免海量行，具体操作仍绑定明确文件及来源，不以泛化通配删除替代。
6. 选择落实到真实保存开关、目录职责和回传清单；若现有输出缺少数据/解释，先补齐交付，再减少其他输出。正式运行结束对照清单，意外新产物单独标出。

smoke是新执行流程、保存策略或相关上游版本变更时的接入验证，不默认每次改学习率/seed都再跑一轮全流程。仍适用的已核结果可复用；输出路径/内容发生变化时按影响范围补查。

### 用途怎样通过实物判断（建议，不设统一评分）

- 人能否用它判断本次实验目标、差异与结果？展示实际表格/图像/例子，不靠文件名证明。
- 是否需要它来重算指标、检查异常、核对样本范围或解释误差？若只留最终图不能复核，应保留必要测量明细和口径。
- 后续阶段、恢复执行或其他实验是否会消费它？此类文件可保留执行端，不必本地可阅读。
- 能否由已经保留的输入/配置/代码准确重建，成本和唯一性如何？确定无消费者的可重建内容才进入关闭/临时/清理讨论。

这些判断形成保存与回传范围，不自动把整个实验标成“重要实验”。远端保留模型也不意味着所有checkpoint永久保留；具体恢复/后续用途仍需说明。不能以“无法直接阅读”或“本次smoke没出现”作为删除证据。
