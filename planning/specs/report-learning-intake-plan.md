### 多类型、多agent推荐：新增要求（2026-11-08）

本轮用户明确要求：

- 推荐不限于论文，也包括项目主页和Blog，例如无公开论文的闭源模型介绍。
- 页面需要热度等辅助信息，包括项目在各平台上的star等指标。
- 推荐由多个独立agent执行；两个Codex对话中的定时任务可以分别推荐各自领域。
- 它们的结果在同一推荐主页汇集，并能通过标签等条件分开查看。
- 定义统一加入接口，供不同agent使用，不依赖某一个对话或执行者。

#### 对象、推荐记录与标签的建议（待确认）

| 内容 | 建议表达 | 用途 |
|---|---|---|
| 推荐对象 | 论文身份或已核实的资源URL；类型包含论文、项目主页、Blog，并预留扩展 | 同一对象只维护一个候选入口 |
| 推荐记录 | 执行者/长期任务身份、本次运行、提交身份、时间和本条推荐的标签 | 同一对象可被多个agent推荐，保留各自记录 |
| 领域标签 | 可多值，如世界模型、3DGS；维护名称和别名，允许增加 | 按研究范围筛选，避免近义标签不断分裂 |
| 资源类型 | 论文、项目主页、Blog等独立字段 | 按材料形态筛选，不与领域混用 |
| 推荐任务 | 稳定任务身份与人类可读名称；宿主/对话链接仅作可选追溯 | 区分两个Codex定时任务，或其他宿主的agent |
| 来源渠道 | 实际发现它的网站、订阅或平台 | 与推荐者分开，能追到原渠道 |
| 人工标签与决定 | 人维护的标签、选择/忽略等决定 | 机器刷新保留人工内容；与agent提交的标签分开 |

同一论文被两个任务推荐时，首页合并一项，并保留两条推荐记录。
筛选“任务A＋世界模型”时，两项条件须命中同一条推荐记录，
不能把任务A推荐时的3DGS标签与任务B推荐时的世界模型标签拼成命中。
筛选和排序分开：可先按领域/任务限定，再按发布时间或某一平台指标排序。

论文、项目主页和Blog即使介绍同一工作，也不直接合并身份或摘要。
经核验可以建立相关链接；同名或相互提及不自动证明它们是同一资源。
这些是入库前候选，正式知识归属继续使用完整资产单元，不新增重复知识主库。

#### 热度的建议（待确认）

每项热度保存平台、指标名、数值、被统计对象的URL及采集时间；
窗口指标另存统计周期。例如GitHub仓库stars属于该仓库，
关联到论文卡片时仍标明对应仓库，不能解释成论文的引用数或认可度。
GitHub公开仓库元数据含stargazers_count，见[官方接口](https://docs.github.com/en/rest/repos/repos#get-a-repository)。

各平台指标分别展示，不直接相加为一个总分；未知保持未知，不填零。
刷新失败保留上次值和时间并显示状态；没有历史观测时不生成增长率或“趋势”。
多个agent推荐次数可单独表达，不能冒充独立研究证据或平台热度。
项目页/Blog没有摘要时使用有出处的原文简介或摘录，若提供译文则标明；

### 待入库清单与不采用（2026-11-08已确认设计，尚未实现）

用户在清单维护及两类不采用理由的讨论后确认“那就ok了”。本节固化该设计；
0.51.0目前只保存未处理、稍后看、已选和忽略，尚无拒绝理由、方向范围、执行领取或入库结果回写。
以下状态与操作须在后续实现后再作产品验收，不改写一期已发布/已验收事实。

#### 人的决定与清单维护

| 人的操作 | 保存与呈现 |
|---|---|
| 尚未决定、稍后看 | 保留为候选，未勾选不能解释为拒绝 |
| 加入待入库清单 | 保存用户选择、摘要审阅上下文和目标位置；尚未写入Zotero或Vault |
| 不采用 | 保存人选择的理由、适用方向/项目、时间和可选备注；可以重新考虑 |

“不采用”先提供已确认的两类理由，不由agent根据热度自动填写：

- **质量不符合要求**：保存人对该资料的判断。重复推荐展示既有判断，不抹去人工内容；
  有新版本时保留旧判断及其对应版本，不把旧版本的判断冒充新版本结论。
- **与当前方向无关**：必须关联人明确选择的方向或项目，只在该范围生效。
  同一资料在其他方向仍可被推荐；不能把一次拒绝扩展成全局屏蔽。

上述范围是明确保存的人工决定；筛选条件或标签偶然共现不能暗中生成适用范围。
沿用已有资源和推荐身份，不复制一份候选或创建另一份知识主库。

#### 执行与结果回写

| 清单状态 | 维护要求 |
|---|---|
| 待入库 | 可修改目标或取消；已确认的目标复用，缺项明确显示并在写入前补齐 |
| 处理中 | 记录真实执行者和正在处理的请求，防止多个agent重复执行；具体领取与中断恢复机制在实现时定义 |
| 已入库 | 按实际请求保存Zotero条目或Vault入口及结果回执，进入完成记录；论文分析和索引等未请求/未完成工作不冒称完成 |
| 需要处理 | 保存失败/部分完成原因和已产生的结果，支持核对后重试；不能整批抹掉成功项 |

多个agent重复推荐同一资料时沿用人工选择与处理记录；完成项不因新推荐自动回到待入库。
执行前仍按既有身份与来源规则查重；取消待办只改变清单，不删除已写入Zotero或Vault的内容。
暂未实现的完成回写不能靠把已选项改回“未处理”来冒充。

页面文案改为“加入待入库清单”，原“忽略”改为“不采用”并填写理由。
日常维护直接在推荐页完成；JSON导出是交接快照，执行者须重新读取同一池当前状态，
不能把旧导出当作仍有效的选择或维护另一份主清单。推荐页面不因此扩展为通用agent控制面。

本轮只更新规划与交接，不修改运行Skill/schema、代码、安装缓存、推荐数据或正式资料，
不发布安装、不切换服务或合并main。后续以合成输入和test Vault原单个外围对象验证；
原论文单元和格式保留，具体测试步骤、预期和影响在执行前说明。
