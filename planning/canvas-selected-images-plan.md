# Canvas 选定图片：独立开发测试

对象仅为既有 v5 合成论文 fixture；不分析、迁移或改写真实文库。
输入是在方法 module 的 method 点附一张合成流程 PNG、在实验 ablation 的 components 点附一张合成表格 PNG。
两者绑定各自已有 PDF 页身份，并声明论文内 attachments 路径、图片 hash 和真实像素尺寸。

预期可见结果：五分支和所有具名文字节点保持；两张图分别是对应论点的可编辑补充卡，
显示题注、图片、同页原文入口和精确正文反链。正文摘录不加入 Canvas；无图片的旧输入不改字节。
图卡使用有界的等比尺寸；仍执行对齐、无交叉/遮挡、420 px 节点高度和整体长宽比门禁。

开发测试步骤：

1. 模型及 JSON Schema 接受上述两类图片，拒绝段落、错误分支、无支持/错页来源、越界/URL 路径和旧版本图片字段。
2. 渲染/校验检查两张图的挂载、来源与反链，以及文字树、正文和空槽守恒；篡改链接、缩小图框或重叠须不通过。
3. 合成临时文件验证真实 PNG 尺寸/hash，缺失、篡改、符号链接须拒绝；canonical 提交前和回执前核验图片，失败恢复分析三文件但不覆盖外部图片编辑。
4. 既有成对更新测试必须继续保持未选内容与人工布局；无法容纳图片的旧布局返回候选冲突，不静默重排。
5. 定向测试通过后做 unit/contract 回归。所有文件写入仅限 pytest 临时目录及开发记录。

这些测试不证明图片裁剪的科学充分性、Obsidian 原生渲染或人工美观通过。
实机必须先正常发布安装 hotfix，再用一个 test Vault 样本展示；当前 V-JEPA 2 canonical 图不在本轮修改范围。
人工评鉴需明确说明打开位置、题注/可读性/链接点击/对齐观察和待确认项；不得用结构通过代替。
